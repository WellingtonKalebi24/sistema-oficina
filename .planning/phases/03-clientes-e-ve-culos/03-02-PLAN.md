## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| authenticated browser to customer/vehicle API | Authenticated users send PII, vehicle identifiers and record IDs to protected endpoints. |
| customer/vehicle relation boundary | Vehicle writes can reference customer IDs that may belong to another tenant or be soft-deleted. |
| route validation to Prisma transaction | Validated API payloads become persisted operational data and audit rows. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-02-01 | Elevation of Privilege | customer/vehicle routes | high | mitigate | Gate every route with Phase 2 `requirePermission` and test missing-permission 403 responses per D-09. |
| T-03-02-02 | Information Disclosure | list/search/detail endpoints | high | mitigate | Derive tenant only from `req.auth.tenantId`; tests prove tenant A cannot read tenant B customers or vehicles. |
| T-03-02-03 | Tampering | vehicle customer link | high | mitigate | Validate both vehicle and customer under the authenticated tenant before linking per D-05. |
| T-03-02-04 | Repudiation | customer/vehicle mutations | medium | mitigate | Write audit records in the same transaction as create/update/delete/link operations and assert action names in tests. |
| T-03-02-05 | Information Disclosure | audit metadata | medium | mitigate | Store changed field names, related IDs and concise reasons, not raw documents, notes, phone bodies or secrets. |
| T-03-02-SC | Tampering | npm installs | high | mitigate | No package installation in this plan; use existing Express, Zod, Prisma and Vitest stack only. |
</threat_model>
