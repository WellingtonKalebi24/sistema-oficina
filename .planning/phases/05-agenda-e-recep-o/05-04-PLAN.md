<objective>
Entregar a fatia vertical de anexos opcionais com armazenamento local protegido, categorias canonicas e acesso exclusivamente por API autenticada.

Output: Instalação de `multer`, declaracao local de tipos, env/Compose de upload root, migration de CheckInAttachment, rotas multipart/download/delete protegidas, cliente FormData e UI de anexos.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser -> multipart API | Arquivo nao confiavel, nome original e categoria cruzam para backend. |
| API -> filesystem | Bytes sao gravados em disco local Docker-compatible. |
| API -> download stream | Bytes saem do servidor somente apos autorizacao e ownership DB. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-16 | Information Disclosure | download route | critical | mitigate | Lookup por tenantId+checkInId+attachmentId antes de stream; nenhum `express.static` para upload root. |
| T-05-17 | Tampering | storage path | high | mitigate | Ignorar originalName para path, gerar storedName por UUID e validar resolved path dentro de `RECEPTION_UPLOAD_ROOT`. |
| T-05-18 | Denial of Service | multer upload | high | mitigate | Route-scoped multer com fileSize/files/fields limits e fileFilter de tipos aceitos para fotos/documentos usuais. |
| T-05-19 | Repudiation | upload/delete | medium | mitigate | Audit rows para `reception.attachments.uploaded` e `reception.attachments.deleted` com filename, category, size e sem bytes. |
| T-05-20 | Elevation of Privilege | attachment mutation | high | mitigate | Permissoes separadas read/write/delete aplicadas no backend; testes provam 403/404. |
| T-05-SC | Tampering | npm installs | high | mitigate | `multer` aprovado em RESEARCH.md; `@types/multer` tem veredito SUS e fica proibido neste plano sem checkpoint humano. |
</threat_model>
