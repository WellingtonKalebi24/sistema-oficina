## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser -> API read/update/detail | Usuario pode tentar IDs de outro tenant ou alterar fatos de recepcao depois da conclusao. |
| API -> AuditLog | Dados de recepcao sensiveis precisam de rastreabilidade sem virar dump de conteudo. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-11 | Information Disclosure | detail endpoints | high | mitigate | `findFirst` por id+tenantId; testes cross-tenant para appointment, check-in e checklist. |
| T-05-12 | Tampering | post-completion edit | high | mitigate | Permissao `reception.checkins.write`, schema finito e audit de campos alterados antes/depois como referencias concisas. |
| T-05-13 | Repudiation | audit rows | high | mitigate | Suites `reception-audit` verificam actions de create/convert/update/cancel e payload sanitizado. |
| T-05-14 | Elevation of Privilege | UI action availability | medium | mitigate | UI esconde por permissao apenas para usabilidade; rotas continuam com `requirePermission` e teste 403. |
| T-05-15 | Information Disclosure | responsive detail modal | low | accept | Dados exibidos sao os mesmos ja autorizados pelo endpoint tenant-scoped; risco residual e de apresentacao local. |
</threat_model>
