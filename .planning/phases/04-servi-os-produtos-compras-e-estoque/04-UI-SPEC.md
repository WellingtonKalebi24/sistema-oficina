## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Required marker gap, icon gaps, tight inline metadata |
| sm | 8px | Button-row gaps, table action gaps, compact stacked controls |
| md | 16px | Default panel padding, grid gaps, form group rhythm |
| lg | 24px | Topbar horizontal padding, large form sections, major panel breaks |
| xl | 32px | Page horizontal gutter on desktop and major content separation |
| 2xl | 48px | Reserved for future large workflow breaks; do not use inside dense Phase 4 panels |
| 3xl | 64px | Not used in Phase 4 operational screens |

Exceptions:
- Form controls keep the existing `min-height: 42px`.
- Mobile nav and touch rows keep the existing 44px-48px minimum target behavior.
- Table action buttons keep the existing compact 32px minimum height.
- Stock movement history rows may use 12px internal padding to preserve scan density.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 | 1.5 |
| Label | 12px | 600 | 1.3 |
| Heading | 20px | 600 | 1.2 |
| Display | 28px | 600 | 1.15 |

Typography rules:
- Use only weights 400 and 600 in new Phase 4 UI. Existing heavier button styling may remain until normalized by a later visual cleanup.
- Page titles stay compact; do not introduce marketing-scale hero type.
- Table headers use the Label role: uppercase, muted, 12px, weight 600.
- Numeric stock values, BRL currency and quantities must align visually in tables and not resize rows when values update.
- Letter spacing remains `0`; do not scale font size with viewport width.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#f4f7f6` | Page background and admin workspace field around panels |
| Secondary (30%) | `#ffffff` and `#eef3f1` | Panels, cards, forms, tables, sidebar/nav, muted filter strips |
| Accent (10%) | `#c58b2f` | Keyboard focus rings, required-field marker companion emphasis, low-stock warning border/icon only |
| Destructive | `#b4343a` | Deactivate, cancel reservation, adjustment danger/error states and destructive confirmations only |

Accent reserved for: focus outlines, calculated low-stock warning badges/strips, unsaved required-field emphasis, active finite-mode selection where primary would imply completion.

Semantic colors:
- Primary `#176b5b`: main submit actions and active navigation.
- Success `#237348`: recorded, available, completed purchase entry and successful stock transaction states.
- Info `#2f66a0`: loading, neutral guidance and read-only history/source-operation metadata.
- Warning uses accent `#c58b2f` only for calculated visual alerts; it must not create notifications, counters, inboxes or message-like UI.

## Phase 4 Interaction Contract

Navigation:
- Add a compact "Estoque" operational nav group or item inside the existing authenticated admin shell.
- Keep the current two-column desktop pattern: left action panel, right table/history panel.
- On mobile, collapse to one column and preserve all required actions; tables may scroll horizontally.
- Do not add a dashboard, notification center or customer communication surface in this phase.

Screen structure:
- Use tabs, segmented controls or existing nav grouping for these Phase 4 work areas: `Servicos`, `Produtos`, `Fornecedores`, `Compras`, `Movimentos`, `Reservas`, `Alertas`.
- Each area uses one primary action panel and one scan-friendly table/list panel.
- Dense forms may use split two-column fields only when each field remains at least 160px wide.

Tables:
- Persisted operational rows use tables, not marketing cards.
- Products table columns: `SKU/Codigo`, `Produto`, `Categoria`, `Estoque fisico`, `Reservado`, `Disponivel`, `Minimo`, `Status`, `Acoes`.
- Services table columns: `Servico`, `Preco base`, `Ativo`, `Atualizado`, `Acoes`.
- Suppliers table columns: `Fornecedor`, `Documento`, `Telefone`, `Ativo`, `Atualizado`, `Acoes`.
- Purchases table columns: `Compra`, `Fornecedor`, `Data`, `Itens`, `Total`, `Entrada`, `Acoes`.
- Movement history columns: `Data`, `Produto`, `Tipo`, `Quantidade`, `Origem`, `Usuario`, `Saldo apos`.
- Use horizontal overflow for narrow screens and keep row heights stable when badges change.

Filters:
- Place filters directly above the table they affect.
- Product filters: search text, category select, status select and low-stock toggle.
- Movement filters: product search, movement type select, source operation text, date range.
- Reservation filters: active/cancelled status and product search.
- Filter submit copy uses `Buscar produtos`, `Buscar movimentos`, `Buscar reservas`.

Forms:
- Every input has a visible label. Required labels include the red `*` marker.
- Services require name and base price.
- Products require name and category; minimum stock is optional but visible in the product form.
- Suppliers require name; document and phone are optional operational identifiers.
- Purchase entry requires supplier, purchase date and at least one item row.
- Stock exit requires product, quantity and origin tracking text.
- Stock adjustment requires product, quantity delta and reason.
- Reservation requires product, quantity and source reference when quote/work-order links are not yet available.
- Keep form validation light in the browser; display backend errors verbatim only when they are safe operator messages.

Stock semantics:
- Show three separate product quantities: physical stock, reserved quantity and available quantity.
- Available quantity is physical minus active reservations; never label it as physical balance.
- Purchase entry success must communicate that the backend updated stock transactionally.
- Reservation success must communicate that physical balance did not change.
- Low-stock alert is a calculated visual badge/strip from stock data only.
- Do not create notification records, bell counters, delivery semantics or message history for low stock.

Permissions and blocked states:
- Hide or disable actions when the session lacks the obvious permission, but always handle backend 403 with the existing blocked panel pattern.
- Unauthorized stock adjustment shows a server-permission blocked state, not a client-only explanation.
- Destructive or critical actions remain auditable by backend rules.

Confirmations:
- Deactivation uses an inline `confirm-strip` or focused modal that names the affected record.
- Reservation cancellation requires explicit confirmation.
- Stock adjustment requires an entered reason before submit and a confirmation if the adjustment can reduce available quantity.
- Destructive buttons use the danger color only.

Loading, empty and error:
- Loading preserves form/table dimensions with compact skeleton rows or inline status text.
- Empty states are text-only and operational; no illustrations.
- Error states must not leak stack traces, connection strings, tokens or Prisma details.
- Success and status messages use `role="status"` or equivalent when they update after an action.

Formatting:
- Dates and times use `formatDateTime` / `Intl.DateTimeFormat("pt-BR", { timeZone: "America/Sao_Paulo" })`.
- Currency uses BRL through `formatCurrency` / `Intl.NumberFormat("pt-BR", { style: "currency", currency: "BRL" })`.
- Quantities use Brazilian numeric input conventions where feasible, but persisted values are validated by the backend.

Accessibility:
- Preserve 3px accent focus outlines.
- Buttons, filters and nav controls must be keyboard reachable.
- Icon-only controls are not allowed in Phase 4 unless they include accessible names and tooltips; prefer text labels for dense operational actions.
- Low-stock state must not rely on color alone; include badge text `Estoque baixo`.
