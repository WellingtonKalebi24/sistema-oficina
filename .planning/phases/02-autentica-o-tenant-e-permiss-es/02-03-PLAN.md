## Phase Goal

**As a** workshop administrator, **I want to** access JO.IA securely with tenant-aware identity and permissions, **so that** each workshop's users, settings and administrative actions stay isolated and auditable.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| authenticated browser to admin API | Authenticated but untrusted users request tenant settings, user and permission changes. |
| tenant A data to tenant B data | Shared database stores records for multiple workshops. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-03-01 | Elevation of Privilege | `users.create` and role assignment | high | mitigate | Enforce `users.createAdmin` before admin-level grants per D-03 and test denial. |
| T-02-03-02 | Information Disclosure | tenant-scoped admin reads | high | mitigate | Every query filters by `req.auth.tenantId`; two-tenant tests cover reads and writes. |
| T-02-03-03 | Tampering | permission overrides | high | mitigate | Override writes require `permissions.manage`, validate tenant relations and audit changes. |
| T-02-03-04 | Repudiation | admin changes | medium | mitigate | Audit tenant settings, user lifecycle, role and override events with sanitized payloads. |
| T-02-03-SC | Tampering | npm installs | high | mitigate | No new package installation in this plan; package gate completed in Plan 02-01. |
</threat_model>
