<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser to public auth API | Untrusted credentials, reset requests and tokens enter Express routes. |
| API to PostgreSQL | Auth secrets, sessions and audit metadata are persisted. |
| API to SMTP | Recovery email leaves the API boundary only for authentication recovery. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-02-01 | Spoofing | `POST /auth/login` | high | mitigate | Argon2id verification, generic failures, rate limiting and sanitized responses. |
| T-02-02-02 | Tampering | `Session` refresh rotation | high | mitigate | Store hashed refresh token, rotate in a transaction and revoke only current session per D-08, D-09 and D-10. |
| T-02-02-03 | Information Disclosure | audit and logs | high | mitigate | Tests assert audit payloads and errors exclude passwords, tokens, reset codes and hashes per D-13. |
| T-02-02-04 | Elevation of Privilege | bootstrap route | high | mitigate | Transactionally reject bootstrap after first tenant/admin exists per D-01. |
| T-02-02-05 | Repudiation | auth lifecycle | medium | mitigate | Audit bootstrap, login, refresh, logout, reset and password change with tenant/user/session metadata. |
| T-02-02-SC | Tampering | npm installs | high | mitigate | Depends on completed Plan 02-01 package gate for `nodemailer` and `express-rate-limit`. |
</threat_model>
