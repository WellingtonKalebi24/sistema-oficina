<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser to public reset API | Untrusted email/reset-code/password input enters auth routes. |
| API to SMTP | Recovery email leaves the API boundary only for authentication recovery. |
| protected browser to API | Bearer access token is converted into backend auth context. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-04-01 | Information Disclosure | password reset | high | mitigate | Generic reset responses, hashed single-use codes, no secrets in audit or errors per D-13. |
| T-02-04-02 | Spoofing | `requireAuth` | high | mitigate | Verify jose claims, active user and active unrevoked session before attaching auth context. |
| T-02-04-03 | Repudiation | auth lifecycle | medium | mitigate | Audit bootstrap, login, refresh, logout, reset and password change with sanitized metadata. |
| T-02-04-SC | Tampering | npm installs | high | mitigate | Depends on completed Plan 02-01 package gate for `nodemailer`. |
</threat_model>
