## Phase Goal

**As a** workshop administrator, **I want to** access JO.IA securely with tenant-aware identity and permissions, **so that** each workshop's users, settings and administrative actions stay isolated and auditable.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser to web app | Operator input controls session state and admin UI actions. |
| web app to API | Browser sends bearer tokens and admin mutations to Express. |
| local runtime to Docker stack | Compose smoke validates db/api/web integration. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-04-01 | Spoofing | web session storage | medium | mitigate | Store only required token material, clear on logout, and rely on API `requireAuth` for authority. |
| T-02-04-02 | Elevation of Privilege | admin menu visibility | medium | mitigate | Menu visibility is UX only; API 403 states are tested and surfaced per D-16. |
| T-02-04-03 | Information Disclosure | UI error states | medium | mitigate | Portuguese errors avoid stack traces, token values, SMTP secrets and reset codes. |
| T-02-04-04 | Tampering | final migration/runtime | high | mitigate | Final gate runs `npm run db:migrate`, `npm run verify` and Docker config/smoke checks. |
| T-02-04-SC | Tampering | npm installs | high | mitigate | No package installation in this plan; package gate completed in Plan 02-01. |
</threat_model>
